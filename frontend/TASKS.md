# Роль 3 — Frontend / UX

Ветка: feat/frontend. Зона: frontend/**.
Начальное состояние: scaffold, интеграционные точки уже созданы; платные вызовы выключены.

## Задачи по порядку

1. Развить index.html + src/: клиентская панель и панель супервизора.
   Можно сохранить vanilla JS; переход на другой toolchain не нужен для MVP.
2. Микрофон через getUserMedia/MediaRecorder: начало/остановка, permission denial,
   отправка multipart file в /api/voice/transcribe; текст — резервный канал.
3. Протянуть transcript → /turns → /voice/synthesize → реальное audio playback.
   Во время scaffold показывать недоступность голосовых endpoints, не имитировать.
4. Trace: ordered selected IDs, reason, alternatives, slots, active/parked topics,
   подтверждения/передача, измеренные задержки по ходам.
5. Измерить конец речи → начало фактического воспроизведения на клиенте.
   Push-to-talk stop — только приближение; явно описать, позже VAD.
   Не выдавать backend_total_ms за total latency.
6. RU/KK UI labels и ответ, смешанная речь, новый разговор, 10-turn limit,
   сетевые ошибки и повторный запрос без дублирования действий.
7. Demo/replay — только записанные трассы фактических прогонов, с меткой Replay.
   Не заменять живой ввод готовыми ответами.
8. src/api.js — единая точка API; все пользовательские строки безопасно рендерить.
9. Записать локально demo checklist и ручные проверки микрофона/динамиков.
   Browser speechSynthesis не гарантирует KK; согласованный основной путь — server TTS.

## Критерии готовности

- Жюри может без объяснений записать реплику и услышать ответ.
- Каждая реплика отображает трассу; видно scaffold/live/replay и ошибки.
- Микрофон, TTS и fallback проверены в реальном браузере на RU/KK/mixed.
- Никаких API-ключей или прямых платных запросов с браузера.
- Изменения ограничены frontend/, контракт с backend сохранён.
