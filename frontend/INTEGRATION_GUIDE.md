# Руководство по интеграции и слиянию: Frontend / UX (Роль 3) → Backend / Platform (Роль 2)

Данный документ предназначен для **интегратора команды Scoundrels (Роль 2)** и **AI-агента бэкенда** для бесшовного слияния ветки `feat/frontend` в `main`.

---

## 1. Резюме проделанной работы

Фронтенд-подсистема RouteMap полностью разработана в соответствии со спецификацией Halyk Bank (кейс Voice Router), контрактами `contracts/models.py` и правилами `docs/OWNERSHIP.md`.

* **Архитектурный стек:** Vanilla JS (нативные ES-модули без сторонних npm/node сборщиков), семантический HTML5, чистый CSS с дизайн-системой токенов.
* **Брендовые стили Halyk Bank / Saqta:**
  * Тёмная тема (`#282828`) и Светлая тема (`#ffffff`).
  * Фирменные цвета: изумрудный `#008265` и янтарный `#E59800` (hover-эффекты на всех кнопках).
  * Чёткая окантовка окон в светлой теме (`2px solid #008265`), исключающая размытие на белом фоне.
  * Фирменный favicon: щит Saqta + звуковые волны роутера.
* **Двуязычность (i18n):** Полный дубляж всех элементов UI, баннеров, статусов и сообщений об ошибках на Русский и Казахский языки (`RU / KK`).
* **Аудио-подсистема:** Push-to-Talk захват микрофона (`MediaRecorder`), замер момента окончания речи ($T_{stop}$), аудиоплеер для ответа ассистента с точной отсечкой старта звука ($T_{play}$).
* **Explainability (Панель супервизора):** Визуализация действий (`route`, `clarify`, `transfer`), primary сценарий, очередь намерений (multi-intent), уверенность (`certainty`), обоснование (`rationale`), топ-3 альтернативы, таблица слотов, стек тем (`active`, `parked`, `resolved`).
* **Метрики и Latency Waterfall:** Точный замер Client End-to-Audio, дефисы `—` для неизмеренных этапов (без фальшивых `0 ms`), расчет сессионных метрик **p50 (медиана)** и **p95** с подсветкой критериев оценки жюри (≤ 1.5 с — +2 балла; ≤ 3.0 с — +1 балл).
* **Безопасность (XSS-safe):** Строгий рендеринг исключительно через `document.createElement` и `textContent` (без уязвимых присваиваний `.innerHTML`).
* **Тестирование:** Автоматические тесты `frontend/tests/test_frontend_assets.py` (4 passed) + демо-чеклист `frontend/tests/DEMO_CHECKLIST.md`.

## 3. Точки сопряжения (Integration Joints) с Бэкендом

Статические файлы отдаются сервером FastAPI по пути `/static/*` (`StaticFiles(directory="frontend/src")`), а корень `/` отдает `frontend/index.html`.

### Эндпоинт 1: `GET /api/health`
* **Вызывается:** при начальной загрузке страницы.
* **Ожидаемый ответ:**
  ```json
  {
    "status": "ok",
    "mode": "scaffold" | "live",
    "schema_version": "1.0",
    "capabilities": {
      "llm_routing": false,
      "stt": false,
      "tts": false
    },
    "catalog_count": 43
  }
  ```
* **Поведение фронтенда:**
  * Если `capabilities.llm_routing === true` → зелёный баннер `Режим Live LLM`.
  * Иначе → жёлтый баннер `Режим scaffold`.

---

### Эндпоинт 2: `POST /api/sessions`
* **Вызывается:** при старте страницы и по кнопке «Новый разговор».
* **Тело запроса:** пустое (или `{}`).
* **Ожидаемый ответ (HTTP 201):**
  ```json
  {
    "session_id": "c1f7a63d-4c3e-4f3b-8d4e-123456789abc"
  }
  ```
* **Поведение фронтенда:** сохраняет `currentSessionId`, сбрасывает локальный счетчик ходов в 0, активирует кнопку отправки.

---

### Эндпоинт 3: `POST /api/sessions/{session_id}/turns`
* **Вызывается:** при отправке текста пользователем или после успешной расшифровки голоса.
* **Тело запроса (`TurnInput`):**
  ```json
  {
    "text": "Хочу оформить страховку ОГПО в Алматы",
    "language": "auto" | "ru" | "kk" | "mixed"
  }
  ```
* **Ожидаемый ответ (HTTP 200, `TurnResponse` по `contracts/models.py`):**
  ```json
  {
    "schema_version": "1.0",
    "session_id": "c1f7a63d-...",
    "turn_id": "T01",
    "mode": "scaffold" | "live",
    "transcript": "Хочу оформить страховку ОГПО в Алматы",
    "language": "ru",
    "assistant_text": "Стоимость полиса ОГПО составляет 18 500 тенге. Оформим?",
    "decision": {
      "action": "route" | "clarify" | "transfer",
      "selected_scenario_id": "SC01",
      "scenario_ids": ["SC01"],
      "rationale": "Клиент запросил расчет стоимости обязательного страхования ОГПО.",
      "certainty": "high" | "medium" | "low" | "unavailable",
      "alternatives": [
        { "scenario_id": "SC02", "reason": "Запрос цены, а не немедленная покупка" }
      ],
      "topic_operation": "create" | "continue" | "switch" | "resume" | "resolve" | "none",
      "slots": [
        { "name": "region", "value": "Алматы" }
      ],
      "clarification_question": null,
      "requires_confirmation": false
    },
    "topics": [
      {
        "topic_id": "T1",
        "scenario_id": "SC01",
        "status": "active" | "parked" | "resolved" | "transferred",
        "slots": [{ "name": "region", "value": "Алматы" }]
      }
    ],
    "timings": {
      "router_ms": 420.5,
      "backend_total_ms": 510.2,
      "stt_ms": null,
      "tts_first_byte_ms": null,
      "end_to_audio_ms": null
    }
  }
  ```
* **Обработка ошибок:**
  * `HTTP 409 Conflict`: сессия исчерпала лимит 10 ходов → фронтенд блокирует ввод, подсвечивает счётчик красным и выводит: «Достигнут лимит 10 реплик для текущей сессии».
  * `HTTP 404 Not Found`: сессия устарела или сервер был перезагружен → фронтенд сообщает об ошибке и предлагает нажать «Новый разговор».
  * `HTTP 422 Unprocessable Entity`: пустой текст.

---

### Эндпоинт 4: `POST /api/voice/transcribe`
* **Вызывается:** после отпускания кнопки `🎙️ Микрофон (PTT)`.
* **Формат запроса:** `multipart/form-data`, поле `file` с аудио (MIME `audio/webm;codecs=opus` или `audio/webm`).
* **Поведение при Scaffold:** бэкенд возвращает **HTTP 501 Not Implemented**. Фронтенд перехватывает его и выводит пользователю честный статус: *«Голосовой ввод (STT) честно возвращает HTTP 501 в scaffold-режиме. Используйте текстовый ввод.»* (интерфейс не ломается).
* **Поведение при подключенном STT (Роль 1):** бэкенд возвращает `HTTP 200`:
  ```json
  {
    "text": "Распознанный текст клиента",
    "language": "ru" | "kk" | "mixed",
    "stt_ms": 350.0
  }
  ```
  Фронтенд автоматически подставляет распознанный текст и передает его в `POST /turns`.

---

### Эндпоинт 5: `POST /api/voice/synthesize`
* **Вызывается:** сразу после получения ответа `assistant_text` от роутера.
* **Тело запроса:**
  ```json
  {
    "text": "Текст ответа ассистента",
    "language": "ru" | "kk" | "mixed"
  }
  ```
* **Поведение при Scaffold:** бэкенд возвращает **HTTP 501 Not Implemented**. Фронтенд просто отображает текстовый ответ в бабле, без аудиоплеера.
* **Поведение при подключенном TTS (Роль 1):** бэкенд возвращает бинарное аудио `audio/mpeg` или `audio/webm` (HTTP 200).
  * *Рекомендация для бэкенда:* пробросьте заголовок `X-TTS-First-Byte-Ms: 280.0`. Фронтенд автоматически считает его и отобразит в графе `TTS First Byte`.
  * При старте воспроизведения звука аудиоплеер фиксирует событие `play` и рассчитывает честный `end_to_audio_ms = performance.now() - speechEndTimestamp`, обновляя статистику p50/p95.

## 4. Запросы фронтенда на согласование (Для Роли 2)

1. **Эндпоинт каталога (`GET /api/catalog`):**
   * Сейчас фронтенд имеет собственный локальный справочник `src/catalog.js` (все 40 сценариев Saqta `SC01..SC40` + 3 системных интента).
   * Если платформа сделает эндпоинт `GET /api/catalog`, фронтенд готов загружать его динамически.
2. **Протокол подтверждения необратимых действий:**
   * Когда LLM возвращает `decision.requires_confirmation == true`, фронтенд выводит предупреждающий баннер. Если платформа реализует подтверждение (например, `POST /api/sessions/{id}/confirm` или явное распознавание согласия), фронтенд готов добавить интерактивную кнопку подтверждения.
3. **Idempotency-Key:**
   * Для предотвращения дублирования реплик при плохой сети желательно поддержать заголовок `Idempotency-Key` или передавать клиентский `turn_id` в запросе.

## 5. Инструкция по слиянию ветки `feat/frontend` в `main`

Интегратор (Роль 2) может выполнить слияние следующими стандартными командами:

```bash
# 1. Получить последние изменения
git fetch origin

# 2. Переключиться на чистую ветку main
git switch main
git pull --ff-only origin main

# 3. Выполнить обычное слияние ветки фронтенда (без fast-forward)
git merge --no-ff origin/feat/frontend -m "merge: integrate feat/frontend into main"

# 4. Проверить запуск тестов
.\.venv\Scripts\python.exe -m pytest -v

# 5. Отправить обновленный main
git push origin main
```

> [!NOTE]
> Конфликты маловероятны, поскольку изменения роли 3 физически изолированы в каталоге `frontend/`. Общие файлы (`contracts/models.py`, `run.py`, `backend/*`) ролью 3 не модифицировались.
