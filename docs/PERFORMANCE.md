# Эксперимент производительности — 23 сентября 2026

Ветка: `feat/try_upgr_perf`, исходная версия: `d76f9ac`.
Модели: `gpt-6-luna`, `gpt-transcribe`, `gpt-4o-mini-tts`, голос `marin`.
Это небольшой локальный эксперимент, не нагрузочное испытание.

## Изменение, включённое в приложении

Озвучка передаётся от OpenAI через FastAPI частями и воспроизводится через
MediaSource до завершения генерации. Старый endpoint полной загрузки сохранён;
браузер без поддержки MP3 MediaSource собирает тот же ответ целиком, без нового
платного запроса. При отключении клиента освобождаются соединение и слот
параллельного запроса. Резерв бюджета списывается один раз.

Маршрут, ответ и панель супервизора появляются сразу после LLM, независимо от TTS.
Для клиентского замера используется событие `playing`; прежнее `play` могло
срабатывать до готовности звука. Начало отсчёта PTT перенесено в вызов stop(),
чтобы учитывать время завершения MediaRecorder. Старые end-to-audio цифры
поэтому не являются строгим A/B-сравнением новой метрики.

## Озвучка в настоящем браузере

Одинаковый текст внутри каждой пары, отдельные платные запросы, без TTS-кэша.
Тексты зафиксированы в `frontend/src/performance.js`. Порядок режимов чередуется.
Время — от начала TTS-запроса до события `playing` в одном браузерном clock.

| Проба | Полная загрузка | Поток | Выигрыш |
|---|---:|---:|---:|
| RU, сначала полная загрузка | 2439 мс | 1164 мс | 1275 мс |
| RU, сначала поток | 1759 мс | 968 мс | 791 мс |
| KK, сначала полная загрузка | 2054 мс | 1201 мс | 853 мс |
| EN, сначала поток | 1466 мс | 1224 мс | 242 мс |

Во всех четырёх потоковых пробах звук начался до конца загрузки. Медиана
полной загрузки — 1906,5 мс, потока — 1182,5 мс (примерно на 38% меньше).
Выборка мала, сетевые задержки и время генерации различаются между запросами.
Это улучшение TTS, а не обещание такой же доли ускорения всей цепочки.

## LLM: испытанные варианты

Чередующиеся последовательные запросы: пять smoke-реплик RU/KK/EN/mixed и
пять ранее добавленных holdout-реплик. По одному исключённому прогреву на профиль.
Первый прогон — 33 запроса, контрольный — 22. p50/p95 рассчитаны по успешным
ответам; сбои отдельно учтены в качестве. Все 43 сценария остаются в промпте.

| Профиль, первый прогон | Верные маршруты | Верный язык | Сбои | p50 | p95 |
|---|---:|---:|---:|---:|---:|
| Исходный, reasoning low | 10/10 | 10/10 | 0 | 3864 мс | 6526 мс |
| Исходный, reasoning none | 10/10 | 9/10 | 0 | 3284 мс | 3994 мс |
| Компактный, reasoning none | 9/10 | 8/10 | 1 | 2427 мс | 3118 мс |

Контрольный компактный `none`: 9/10 маршрутов, 8/10 языков, повторный
`incomplete` на S002, p50 2316 мс. Компактный `low`: 10/10 маршрутов и языков,
без сбоев, p50 3806 мс. Выигрыш компактного `low` относительно исходного
недостаточно убедителен на такой выборке.

Поэтому приложение сохраняет исходный профиль: reasoning `low`,
`OPENAI_ROUTER_COMPACT_OUTPUT=false`. Компактный формат доступен для дальнейших
экспериментов и сохраняет внешние поля API, проверку ID, язык, слоты и
confirmation-политику каталога. Полные 104 dev-реплики и 40 ходов диалогов
с экспериментальными профилями ещё не прогонялись.

## Повторение

Бесплатные проверки из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
node --test frontend/tests/audio_stream.test.mjs
```

Результат: 81 Python-тест и 4 JS-теста. Node 22.7+ нужен только для JS-тестов,
само приложение запускается без Node. Проверены раннее воспроизведение,
буферный fallback, отмена загрузки, освобождение ресурсов и совместимость контрактов.

Для сравнения в браузере запустите `APP_MODE=live` и откройте
[проверку TTS](http://127.0.0.1:8000/static/performance.html): одно нажатие = 2 TTS-запроса.

```powershell
.\.venv\Scripts\python.exe -m backend.router.evals.performance --live --repeats 1
.\.venv\Scripts\python.exe -m backend.platform.evals.stream_smoke --live --audio path\to\recording.mp3
```

Первый CLI ограничен 33 LLM-запросами по умолчанию; `--profiles` и `--repeats`
меняют явно выводимый предел. Второй делает один STT, один LLM и один TTS на
уже запущенном localhost:8000. Отчёты сохраняются в игнорируемой папке `artifacts/`.

Основания реализации: [OpenAI streaming TTS](https://developers.openai.com/api/docs/guides/text-to-speech),
[оптимизация задержки](https://developers.openai.com/api/docs/guides/latency-optimization),
[параметры gpt-6-luna](https://developers.openai.com/api/docs/models/gpt-6-luna).
