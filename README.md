# RouteMap — голосовой маршрутизатор для Saqta Insurance

Проект команды **Scoundrels** для HackAlem AI, трек «Коммуникации», кейс Voice
Router от Halyk Bank. RouteMap помогает клиенту вымышленной страховой компании
Saqta задать вопрос голосом или текстом. Система распознаёт речь, **LLM выбирает
один или несколько из 40 бизнес-сценариев и 3 системных намерений**, сохраняет
темы разговора, формирует осторожный ответ и озвучивает его. Супервизор видит
маршрут, альтернативы, слоты и измеренные задержки.

Особенность решения — разговор не теряет предыдущую тему: можно переключиться,
разобрать срочный вопрос и вернуться к отложенной теме. Поддерживаются русский,
казахский, английский и смешанные реплики; интерфейс локализован на RU/KK.
Сценарий выбирает LLM, не классификатор ключевых фраз.

## Попробовать за 5 минут

Нужны Python 3.11/3.12, микрофон для голосового сценария и ключ OpenAI для
`live`-режима. Node.js и Docker не нужны. Команды из корня репозитория:

```powershell
git clone https://github.com/BAITC-Hacks/hack-22e0bf81-scoundrels.git
cd hack-22e0bf81-scoundrels
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
Copy-Item .env.example .env
```

Если `.env` уже существует, не копируйте пример поверх него. В `.env` впишите
**свой** `OPENAI_API_KEY` и поставьте `APP_MODE=live`.
Проверьте также `OPENAI_STT_MODEL=gpt-transcribe`, если ваш `.env` создан
раньше. Модели в примере уже выставлены: `gpt-6-luna` для маршрута,
`gpt-transcribe` для речи и `gpt-4o-mini-tts` для ответа. Ключ остаётся
только на сервере и не отправляется в браузер/Git. Затем:

```powershell
.\.venv\Scripts\python.exe run.py
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000) и разрешите доступ
к микрофону. Вкладка [API](http://127.0.0.1:8000/docs) показывает все эндпоинты.
На Linux/macOS вместо `Copy-Item` используйте `cp`, а исполняемый Python —
`.venv/bin/python`. Запуск без `.env` или с `APP_MODE=scaffold` бесплатный,
но LLM/голос не вызываются: UI честно показывает ограничения режима.

## Как показать жюри

1. Убедитесь, что `/api/health` показывает `mode: live` и три возможности
   `llm_routing`, `stt`, `tts` равны `true`.
2. Создайте разговор. Напишите «Действует ли мой полис?» — система должна
   выбрать `SC25` и попросить номер полиса и зарегистрированный телефон, не
   выдумывая статус. Панель супервизора показывает обоснование и слоты.
3. Скажите в микрофон: «Сәлем, полисімді тексеріңізші, and I need to change my
   phone number». После отпускания кнопки должны появиться транскрипт,
   сценарии `SC25` и `SC29`, ответ и его озвучивание. Изменения данных
   **не выполняются** без отдельного подтверждения.
4. Начните новый разговор и спросите «Я только что попал в аварию, что
   делать?» — проверьте приоритет срочного `SC11` и безопасный совет.
5. Спросите «Соедините с оператором» — система честно обозначит, что
   передача оператору в этом демо симулируется.
6. Откройте waterfall задержек: `end-to-audio` появляется только после
   фактического начала воспроизведения в браузере, не подменяется временем API.

Одна сессия ограничена 10 репликами. После перезапуска сервера сессии в памяти
сбрасываются. Для отдельной платной проверки HTTP-пути на вашей записи:

```powershell
.\.venv\Scripts\python.exe -m backend.platform.evals.live_smoke --live --audio path\to\recording.webm
```

Команда делает ровно один проход STT → LLM → TTS; отчёт и MP3 сохраняются
локально в игнорируемой Git папке `artifacts/`.

## Что внутри

```text
браузер (MediaRecorder, UI, метрики)
  → FastAPI upload → OpenAI STT → LLM Router (Structured Outputs)
  → состояние тем + безопасный ответ по данным Saqta
  → OpenAI TTS → воспроизведение в браузере
```

- Backend: Python, FastAPI, Pydantic, OpenAI SDK. Раздельные модули
  `backend/router/`, `backend/voice/`, `backend/platform/`.
- Frontend: HTML/CSS/vanilla JavaScript, MediaRecorder, панель супервизора,
  RU/KK локализация, сценарии демо и замер клиентской задержки.
- Данные: неизменённый официальный набор `case_2/voice_router_dataset/`:
  сценарии, база знаний, тестовые клиенты/полисы, 104 dev-реплики и 10 диалогов.
  Дата «сегодня» в наборе — **2026-10-01**.
- Никаких реальных банковских/страховых транзакций: это симулятор.

## Проверки и результаты

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Локально: **75 offline-тестов** по контрактам, роутеру, голосовым адаптерам,
HTTP-интеграции и фронтенду. Они не тратят API-бюджет. Маршрутизатор на
`gpt-6-luna` достиг **104/104** на официальных dev-репликах после настройки
промпта; replay дал **40/40** маршрутов в 10 диалогах. Ограниченный живой
HTTP-прогон смешанной KK/EN записи вернул `[SC25, SC29]` и MP3-ответ. Это
проверки на доступных данных, а не гарантия результата на скрытом наборе.

Повторить платную оценку маршрутизатора можно через
`python -m backend.router.evals.official --live --max-items 104` после проверки
настроек и своего бюджета. Подробности: [router eval](backend/router/evals/README.md)
и [voice eval](backend/voice/evals/README.md). API-ключ для `pytest` не нужен.

Задержка пока не бонусная: в одной смешанной HTTP-пробе STT ≈1.56 с,
LLM ≈4.42 с, первый байт TTS ≈1.12 с. Это **не** end-to-audio:
полное время измеряет браузер от конца речи до начала звука. Цель ≤1.5 с
остаётся задачей оптимизации, а не заявленным достижением.

## Безопасность, расходы и ограничения

`APP_MODE=scaffold` — режим по умолчанию, без платных вызовов. `live` требует
ключ, проверенные модели и положительные лимиты. Локальный счётчик заранее
резервирует условные суммы на каждый вызов и прекращает новые вызовы при
исчерпании `SESSION_BUDGET_USD`/`RUN_BUDGET_USD`; браузер привязывает все три
вызова к сессии, а прямые voice-вызовы без `X-Session-ID` учитываются только
в общем лимите запуска. Параллельно допускаются не
более двух платных запросов, автоматические retries отключены. **Это не
точный счёт OpenAI и не внешний hard cap:** установите также spending limit
в своём OpenAI project. Голосовая запись ограничена 1 MiB, озвучиваемый
текст — 500 символами.

Реализованы безопасные read-only ответы для статуса тестового полиса и
обращения (номер + совпадающий телефон), адресов офисов и способов оплаты.
Остальные сценарии сейчас дают короткие подсказки из официального каталога;
необратимые действия, SMS и реальная
очередь операторов **не выполняются**. Это важно для честной демонстрации:
маршрутизация работает, но полноценный исполнитель всех 40 сценариев ещё
не завершён. Английские ответы — дополнительная возможность, тогда как
исходное ТЗ в первую очередь проверяет RU/KK. Произношение на живом
микрофоне и в шуме нужно оценить человеку на демо-машине.

GitHub Actions ранее не стартовали из-за блокировки биллинга аккаунта;
локальный `pytest` — проверенный на данный момент источник результата.
